## Detailed Findings

### 1. Flash Record Header Structure (16 bytes)

```
Offset  Size  Field           Description
------  ----  -----           -----------
0x00    4     magic           0x464473<kind> (little-endian; low byte = kind)
0x04    4     checksum        CRC-32 over record[0:length], this word zeroed
0x08    4     length          TOTAL record size incl this 16-B header (WO-4)
0x0C    4     address         PRIMARY record's flash address (backups point
                              at the primary, not at themselves) (WO-4, K2)
```

**Observed Record Types**:
- Kind 0x14: Plane parameters (5180 bytes)
- Kind 0x11: Temperature calibration data
- Kind 0x12: Device configuration
- Kind 0x13: Compensation coefficients

### 2. Checksum Algorithm

**Table Location**: 0x2ceb980 in vendor binary
**Polynomial**: 0xEDB88320 (standard CRC-32, reflected)
**Initialization**: 0xFFFFFFFF
**Final XOR**: 0xFFFFFFFF

**Implementation** (from disassembly at 0x23f3a0-0x23f3d4; standard reflected
CRC-32, == `zlib.crc32`):
```c
uint32_t crc = 0xFFFFFFFF;
for (int i = 0; i < N; i++) {              // N = coverage length, see below
    uint8_t index = (crc ^ data[i]) & 0xFF;
    crc = (crc >> 8) ^ crc_table[index];
}
return crc ^ 0xFFFFFFFF;
```

**Coverage (SOLVED — WO-4, 2026-10-24)**: the algorithm was never in doubt;
the earlier failure was the **data range**. The CRC runs over:

```
crc = CRC32( record[0 : length] )   with bytes[4:8] (the checksum word) zeroed
```

Two corrections, both pinned against the reassembled bytes from the recorded
opcode-25 flash reads (session4 capture, 120 reads):

1. The header `length` field (+0x08) is the **TOTAL record size INCLUDING the
   16-byte header** — not the payload size. For the plane record, length = 5180
   = header(16) + payload(5164).
2. The CRC runs from **offset 0** (over the header too), with only the 4-byte
   checksum word zeroed — not over `payload[16:]`. (This matches the write-side
   recipe already stated in calibration-store.md §1.1; WO-4 confirms it and
   pins `length` = total.)

The prior attempt computed CRC over `payload[16:16+len]`, which fails on every
record.

wire-observed 2026-10-18]`:

**Reproducibility (WO-4)** — the table and the 0x215000 all-zero result below
are regenerated by this self-contained script from the recorded capture
(`~/DevReposiMac/raptor-protocol-capture/session4/small_payloads.tsv`; reads the
120 opcode-25 flash frames, reassembles by flash address, runs `zlib.crc32`):

```python
#!/usr/bin/env python3
# python3 crc_verify.py /path/to/session4/small_payloads.tsv
import sys, struct, binascii, zlib, os
TSV = os.path.expanduser(sys.argv[1] if len(sys.argv) > 1 else
    "~/DevReposiMac/raptor-protocol-capture/session4/small_payloads.tsv")

def mp(b, i=0):                     # minimal msgpack -> (value, next_index)
    t = b[i]
    if t < 0x80 or t >= 0xe0: return (t if t < 0x80 else t-256), i+1
    if 0x90 <= t <= 0x9f:
        n=t&0xf; j=i+1; a=[]
        for _ in range(n): v,j=mp(b,j); a.append(v)
        return a,j
    if 0xa0 <= t <= 0xbf: n=t&0x1f; return bytes(b[i+1:i+1+n]), i+1+n
    if t==0xc0: return None, i+1
    if t in (0xc4,0xd9): n=b[i+1]; s=i+2
    elif t in (0xc5,0xda): n=struct.unpack('>H',b[i+1:i+3])[0]; s=i+3
    elif t in (0xc6,0xdb): n=struct.unpack('>I',b[i+1:i+5])[0]; s=i+5
    elif t==0xcc: return b[i+1], i+2
    elif t==0xcd: return struct.unpack('>H',b[i+1:i+3])[0], i+3
    elif t==0xce: return struct.unpack('>I',b[i+1:i+5])[0], i+5
    else: raise ValueError('mp 0x%02x@%d'%(t,i))
    return bytes(b[s:s+n]), s+n

def vendor(v, out):                 # bytes blobs starting with a vendor magic
    if isinstance(v, bytes):
        if v[:2] in (b'GM', b'RB'): out.append(v)
    elif isinstance(v, list):
        for e in v: vendor(e, out)

req_addr, resp = {}, {}
for line in open(TSV, 'rb'):
    p = line.rstrip(b'\n').split(b'\t')
    if len(p) < 4: continue
    try: raw = binascii.unhexlify(p[3].strip())
    except binascii.Error: continue
    if b'\x19\x00' not in raw: continue
    try: val,_ = mp(raw)
    except Exception: continue
    blobs=[]; vendor(val, blobs)
    for blob in blobs:
        if blob[4:6] != b'\x19\x00': continue      # opcode 25 only
        rid = struct.unpack('<H', blob[6:8])[0]
        if blob[:2]==b'GM': req_addr[rid]=struct.unpack('<I',blob[8:12])[0]
        else:               resp[rid]=blob[10:]    # drop 10-byte BR header
mem={}
for rid,data in resp.items():
    a=req_addr.get(rid)
    if a is None: continue
    for k,byte in enumerate(data): mem[a+k]=byte

def rd(a,n): return bytes(mem.get(x,0) for x in range(a,a+n))
RECS=[0x0b0000,0x200000,0x202000,0x204000,0x20a000,0x20e000,0x211000,0x213000]
print("addr        kind  length  stored        computed      result")
for s in RECS:
    magic,crc,length,addr = struct.unpack('<IIII', rd(s,16))
    rec=bytearray(rd(s,length)); rec[4:8]=b'\x00\x00\x00\x00'   # zero cksum word
    comp=zlib.crc32(bytes(rec))&0xffffffff                      # over record[0:length]
    print(f"{s:#010x}  {magic&0xff:#04x}  {length:6d}  {crc:#010x}  {comp:#010x}  "
          f"{'PASS' if comp==crc else 'FAIL'}")
z=rd(0x215000,16)
print(f"\n0x215000 header (16 B): {z.hex()}  -> "
      f"{'all-zero (no record)' if z==bytes(16) else 'nonzero'}")
```

### 3. Temperature Compensation

**Function**: `LineLaserTempCompensator::temp_comp_control()` at 0x28992c

**Threshold**: 0.2°C (IEEE 754 float: 0x3E4CCCCD)

**Algorithm**:
1. Load current temperature from 3 sensors (offsets 0xa0, 0xa4, 0xa8)
2. Compare with baseline temperature
3. If |delta| > 0.2°C for ANY sensor, trigger recomputation
4. Apply compensation coefficients to laser plane parameters

**Sensor Monitoring**:
```
Offset 0xa0: Sensor 1 temperature
Offset 0xa4: Sensor 2 temperature
Offset 0xa8: Sensor 3 temperature
```

### 5. Plane Parameter Struct — DECODED (WO-4, 2026-10-24)

**Flash record**: 0x211000 (primary) / 0x213000 (backup), magic 0x46447314,
total 5180 B = 16-B header + 5164-B payload.
**Live user copy**: 5120 B (0x1400), device-param cache +0x10, via
`get_line_laser_light_plane_param` @0x1eb208.

Decoded from the reassembled flash bytes `[inferred, wire-observed 2026-10-18]`:

**Payload layout** (after the 16-byte record header):
```
payload +0x000..+0x13f : header/preamble
    +0x00  u32 = 18 (0x12)      [open — version or group count; note != 29 planes]
    +0x04  u32  nonzero, differs primary vs backup   [open]
    +0x08..+0x13c : zero
payload +0x140 onward  : array of 40-byte plane entries, in 3 groups
    separated by zero-filled entries; trailing zero padding to record end.
```

**Per-plane entry — 40 bytes = 10 × float32**:
| local off | field | observed range | meaning |
|-----------|-------|----------------|---------|
| +0x00 | f0 | 0 .. 0.14 | per-plane residual / weight [inferred] |
| +0x04 | f1 | 42 .. 66 | laser-line extent, mm [inferred] |
| +0x08 | f2 | −20 .. +17 | lateral center offset, mm [inferred] |
| +0x0c | f3 | 5.6 .. 9.6 | second extent, mm [inferred] |
| +0x10 | f4 (nx) | | **plane unit normal x** [settled] |
| +0x14 | f5 (ny) | | **plane unit normal y** [settled] |
| +0x18 | f6 (nz) | | **plane unit normal z** (\|n\|=0.99999 measured) [settled] |
| +0x1c | f7 (d) | 76 .. 90 | **plane offset, mm**: n·X = d [settled] |
| +0x20 | f8 | 0 | reserved / padding |
| +0x24 | f9 | 0 | reserved / padding |

Plane equation in **camera coordinates** (same frame as the depth intrinsics):
`n·X = d`, `|n| = 1`, d and X in millimetres.

**Plane count — recomputed from the 0x211000 / 0x213000 payload bytes** (an
entry counts as a plane iff its normal at +0x10 is unit, |n|−1 < 1e-3). Offsets
are payload-relative; convention is **start-inclusive, end-exclusive**, each
entry 0x28 B:

PRIMARY 0x211000 — **29 planes in 3 groups** (= the three laser-line projectors;
the "three 8-float tables" of `ConvertScannerCalibParams2LineLaserParams`
@0xd11b74 are really 10-float/40-byte entries):

| group | first entry | last entry | end (excl) | count | normal ≈ |
|-------|-------------|------------|------------|-------|----------|
| 1 | +0x140 | +0x2d0 | +0x2f8 | 11 | (±0.852, ∓0.497, ±0.164) |
| 2 | +0x3e8 | +0x578 | +0x5a0 | 11 | (±0.843, ±0.510, ±0.170) |
| 3 | +0x690 | +0x780 | +0x7a8 | 7  | (±0.970, ∓0.029, ±0.240) |

Total = 11 + 11 + 7 = **29** (not 26: groups are 11/11/7, confirmed by the
unit-normal test on every 40-B slot). The slot right after group 1 (+0x2f8) has
only its first float set (0.0223) and no normal — a trailing scalar, not a 12th
plane. Within each group the nx sign flips halfway (two sweep directions) and d
sweeps ~76–90 mm.

BACKUP 0x213000 — **22 planes (11 / 11 / 0)**: groups 1 and 2 at the same
offsets (values differ slightly from the primary), but the group-3 region
(+0x690..+0x7a8) is **all-zero** — captured 280/280 bytes, zero nonzero, and the
record's CRC validates over those zeros. So the backup carries only the first
two laser-line groups; group 3 is absent, not a reassembly gap.

**Flash-vs-live size (corrects OQ-S15a's "60 bytes")**: payload is 5164 B
(5180 total − 16 header), live copy 5120 B → real gap is **44 bytes**, the
payload preamble (+0x000..+0x13f) the cache largely drops. The earlier 60 came
from treating 5180 as the payload. Exact elided bytes [open] — needs a runtime
hexdump of the 5120-B cache struct.

**Primary ≠ backup**: 0x211000 and 0x213000 are NOT byte mirrors. In groups 1–2
(the 22 planes both carry) normals differ 1e-4..7e-3 and d by 0.01..0.4 mm; and
the backup has **no group 3 at all** (zeroed, see above). The backup is a
distinct calibration (fewer laser-line groups, slightly different values),
matching the differing checksums.

**Status**: ✅ Layout + geometry SOLVED (OQ-S15a). Coefficient names f0–f3 and
the 44-B elision remain open.
